# 总体架构

本文约定 opencode-observer 的职责边界、模块依赖、观测契约和运行约束，用于指导实现与重构。当前支持 run、interaction、LLM、tool、compaction 和 permission.check 六类 span。

- [Trace Schema](schemas/trace.md) 定义可观察行为、trace 拓扑、生命周期和导出字段。
- [适配层设计](adapter.md) 定义源数据识别、模型采集和跨对象协调机制。
- [README](../README.md) 定义配置方式、启用条件和使用限制。
- 本文定义这些要求由哪一层承担。内部实现可调整，但不得隐式改变上述行为与数据口径。

## 1. 设计原则

- **行为识别与遥测分离**：适配层识别业务行为及其生命周期，遥测层依据契约调用管理 span，不重复推断业务边界。
- **契约独立**：层间只传递已识别的行为和 SDK 无关的数据，使宿主适配与遥测实现能够独立演进、测试。
- **以证据为准**：只记录有源数据支持的行为、时间和关联，缺失时按 Trace Schema 降级或省略。
- **不干扰宿主**：遥测和正文采集默认关闭；采集、导出及诊断失败不得影响 OpenCode 的执行。

使用 TypeScript 和 Bun，通过模块边界落实分层，无需拆包或引入跨进程通信。

## 2. 职责与依赖

三层之间的代码依赖如下，箭头表示“依赖于”：

```text
adapter → contract ← telemetry
```

### 2.1 三层职责

| 层     | 负责                                                               | 不负责                                                      |
| ------ | ------------------------------------------------------------------ | ----------------------------------------------------------- |
| 适配层 | 接入宿主，解析源数据，识别对象身份、归属、开始、更新、结束及结果   | 创建或修改 OTel 对象，编码遥测属性，透传原始 SDK 对象       |
| 契约层 | 定义对象引用、数据、操作及其语义                                   | 处理源事件，维护运行状态，执行网络请求                      |
| 遥测层 | 实现契约，维护对象到 span 的映射及上下文，编码数据，导出并清理资源 | 重新识别业务行为，读取源 SDK 对象，通过宿主 client 补查数据 |

适配层可以维护行为状态，遥测层可以维护 span 状态。例如，上下文溢出（overflow）能否恢复由适配层判断；确认任务失败后才提交结束操作，遥测层据此结束 span。

### 2.2 跨层依赖边界

下表为各目录允许的依赖，未列出的跨层依赖均禁止；类型导入、重导出和动态加载同样受限。

| 目录             | 允许的依赖                                 |
| ---------------- | ------------------------------------------ |
| `src/adapter/`   | 本层、契约、OpenCode SDK、AI SDK、平台库   |
| `src/contract/`  | 本层契约类型                               |
| `src/telemetry/` | 本层、契约、OTel SDK、平台库、包版本元数据 |
| `src/user/`      | 本模块、平台库                             |

`user` 是三层之外的独立身份模块，由插件初始化模块装配，见第 3 节。

### 2.3 各层内部组织

#### 适配层（`src/adapter/`）

内部依赖方向为 `opencode → trackers → model → shared`，允许越级使用下游模块，禁止反向依赖：

- `opencode`：接入宿主 hooks/events，负责事件分发、session 关联、恢复判断及跨对象协调。
- `trackers`：负责自身观测对象的行为识别与生命周期跟踪，可以接收并解析相关的源 SDK 对象，也可以使用已解析的数据。所有 tracker 遵循同一职责与依赖边界；全局事件分发和跨对象协调由 `opencode` 协调模块负责，tracker 不直接创建或调用其他 tracker。
- `model`：接入 AI SDK 回调，解析消息与请求、归一化用量并处理传播字段，不依赖 tracker。LLM 与压缩摘要共用用量归一化规则。
- `shared`：提供适配层内部共用的数据快照、错误归一化、数值校验和错误隔离。

以上模块均属于适配层。tracker 必须将观测结果转换为 SDK 无关的契约数据，通过注入的 Observer 接口提交，不直接依赖遥测实现；对应的 span 状态和导出由遥测层管理。

每个 coordinator 只创建一组 run、interaction、LLM、tool、permission 和 compaction tracker，跨 run 复用行为对象及其回调连接。各 tracker 自己持有数据；interaction、LLM、tool、permission 和 compaction 的数据按 `(sessionID, runID)` 分区，不建立集中业务状态模型。coordinator 的 `SessionState` 只保存活动 run 引用、父工具及 overflow 恢复信息。

coordinator 在接受新 run 时显式调用各 tracker 的 `open(run)` 登记数据分区。事件处理、归属查询及收尾操作携带完整 run 引用，只使用已有分区。`close` / `finish` 提交观测结果，`release(run)` 释放该 run 的全部数据。tracker 不提供实例关闭时的数据清理接口。`shared/runs.ts` 仅提供各 tracker 独立使用的分区容器，不保存共享业务数据；具体数据类型和识别规则留在对应 tracker 中。

跨对象归属由 coordinator 查询并解析，再作为数据传入 tracker；tracker 不接收其他 tracker 的查询、解析函数或返回归属的回调。tracker 可以暴露自身的归属查询，以及 `unresolved(run)` 所需关联线索；coordinator 在相关证据到达后调用 `associate` 补齐归属。已有归属在提交观测对象后固定。`onFinish`、`onTask` 等回调只通知生命周期变化，由 coordinator 安排清理和绑定，不用于反向获取归属。

#### 契约层（`src/contract/`）

由观测操作与对象引用、结构化消息与数据类型组成，只表达层间协作所需的语义。契约类型可在本层复用，不包含 tracker、SDK 接入或 span 实现；接口约束见第 4 节。

#### 遥测层（`src/telemetry/`）

内部依赖方向为 `factory → observer → spans`：工厂装配 OTel SDK/exporter，Observer 实现观测契约并协调记录、导出与关闭，span 模块维护遥测状态及数据映射。span 模块不反向依赖工厂或 Observer。

这里的 Observer 是契约的具体实现，其接口定义仍属于契约层。OTLP 编码和传输使用 SDK/exporter，不自行实现协议。

## 3. 配置与装配

本文所称**插件初始化模块**，对应 [src/index.ts](../src/index.ts)，通过 OpenCode 加载插件时调用的 `ObserverPlugin` 完成初始化与装配。它统一读取配置、解析身份、创建遥测实现并通过观测契约注入适配层，连接日志并返回适配层提供的宿主 hooks。

插件初始化模块可以同时依赖配置、用户身份、适配层和遥测层以完成装配。插件初始化模块和配置模块不承载行为识别或遥测实现；事件处理必须经契约调用，不能借装配逻辑绕过边界。

各层定义自身需要的配置类型，由插件初始化模块传入数据，不反向依赖根目录的配置解析逻辑。遥测关闭时不创建实现或注册采集逻辑；开启后才加载 OTel 等较重依赖。支持的模型路径按需接入 SDK 回调，正文关闭时仍可观察显式输出类型。

用户身份模块独立于三层，由插件初始化模块直接调用。环境配置解析与 HTTP 查询分离；查询负责响应校验、超时和有限重试，不读取 provider 配置，也不维护跨调用缓存或冷却状态。查询结果须区分成功、最终失败和跳过查询，避免把不同情况统一当作空值。初始化模块将查询结果与静态配置合并进 `spanAttributes`，tracker 和观测契约不读取、保存或传递 user ID。

## 4. 观测契约

契约以行为为单位提供开始、更新、结束操作，以及上下文传播、刷新和关闭能力。完整接口与类型见 [Observer 契约](../src/contract/observer.ts)，本文约束其语义，不重复维护类型定义。

- **标识与关联**：对象 ID 稳定且明确作用域；更新、结束和父子关系使用精确引用，不按调用时的“当前交互”猜测归属。
- **时间**：统一使用 Unix epoch 毫秒，明确区分源发生时间和本地观察时间，不以异步处理或导出时间替代。
- **更新**：明确快照替换和增量追加语义；增量可去重，重复输入保留首次快照。区分未提供、已知为空与明确清除，提交后的快照不受源对象后续修改影响。
- **终态**：错误使用结构化契约数据，不传源异常对象。重复结束或迟到更新不得重建、改写已结束对象；对象结束不等于网络导出成功。
- **抽象边界**：契约不接收原始事件，不暴露 OTel 对象或通用 span 操作。属性名称、span kind、状态及序列化由遥测层按 Trace Schema 映射。

`captureContent` 同时约束适配层和遥测层，统一控制正文、LLM 工具定义及模型请求/响应 headers；关闭时不为遥测解析、保留、传递或导出这些内容。显式输出类型不受该开关控制。未采集数据不能由自定义属性补造，内建派生字段不能被覆盖；具体字段范围见 [Trace Schema](schemas/trace.md#12-类型内容采集与缺省值)。

## 5. 身份与上下文传播

### 5.1 身份快照

插件初始化模块等待身份查询和有限重试完成后创建遥测实现，查询失败后继续启动。查询结果与身份开关使用固定快照，不随环境变量变化自动刷新，也不回填既有 span，以保持同一实例内身份一致。

| 通道                           | 职责与来源                                                                                                 |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| span 的 `user.id`              | 插件初始化模块合并查询结果与静态配置，通过通用 `spanAttributes` 交给遥测层；六类 span 均使用这份初始化快照 |
| 出站 `tracestate` 的 `user_id` | 插件初始化模块将动态查询结果与开关快照交给适配层，由适配层编码；不以静态 span 属性替代动态身份             |

两个通道的未知值处理不同，须遵循 [身份字段规则](schemas/trace.md#22-公共-attributes) 和 [传播规则](schemas/trace.md#33-根上下文与下游传播)。遥测层不参与身份查询，不增加专用身份回调或 processor；身份查询和出站身份写入共用开关，独立于正文采集。

### 5.2 传播边界

顶层 run 从空上下文创建独立 trace；前台子 run 仅通过明确关联的活动 task 工具继承父 trace，不恢复外部 trace 上下文配置。

模型请求发出前，适配层通过 `llmTraceHeaders` 同步取得指定活动 LLM 的 W3C 字符串字段。遥测层使用实例内 propagator 序列化该 span，不依赖全局 active context；引用未知、已结束或实现已关闭时不返回传播字段。

适配层负责将字段写入请求，并按身份开关处理出站 `user_id`。此过程不修改契约返回对象、OTel SpanContext 或导出 traceState。无法唯一关联时不传播；关闭身份开关不影响 traceparent，正文开关不影响传播。native 路径及同名 headers 冲突的当前限制见 [Trace Schema §3.3](schemas/trace.md#33-根上下文与下游传播)。

## 6. 执行、刷新与关闭

### 6.1 执行与失败隔离

观测记录在本地同步处理；触发刷新的事件回调在记录完成后等待 `Observer.flush()`。导出队列、超时及失败处理由遥测层统一管理，各 hook 不自行排队、重试或操作 provider。

宿主 hooks 和 SDK 回调边界均须隔离同步异常与异步拒绝；事件内的刷新由外层 hook 统一保护。日志不阻塞回调，其自身失败直接忽略。进程内共享回调按监听器隔离失败，保护内部关联标识的清理，诊断只发送给仍活动的实例。观测不得修改 hook 的业务输出，传播所需的请求 headers 按第 5.2 节处理。

失败隔离以宿主入口、后台异步任务和独立监听器为边界。同一同步处理阶段共用保护；未被调用方等待的后台任务单独处理失败，字段降级直接安全上报错误。

### 6.2 生命周期契约

| 接口                        | 语义                                                                          |
| --------------------------- | ----------------------------------------------------------------------------- |
| `flush(): Promise<void>`    | 异步刷新 SDK 缓冲区中已结束的数据，不结束活动对象；触发刷新的事件回调等待完成 |
| `shutdown(): Promise<void>` | 清理未完成对象，由 SDK/exporter 排空并关闭；                                  |

适配层在 session idle、error 或删除后触发刷新。协调器在宿主 `dispose` hook 内统一关闭：先注销模型采集监听器，再调用注入的 `Observer.shutdown()`。遥测层按实际父子关系结束活动 span，再异步等待导出并关闭资源。重复调用返回同一个关闭 Promise。插件初始化模块只负责装配，不再中转关闭回调。

关闭只要求完成观测收尾、解除外部订阅并停止向已关闭实例提交采集数据，不主动清空 tracker、session registry 或 SDK 请求缓存。宿主和异步任务不再持有实例后，剩余纯数据由垃圾回收处理。正常运行期间移除已结束对象、释放父子绑定及清理所属 run 的上下文仍属于生命周期管理。

Observer 统一持有已结束 span 的历史记录，按 run、span 类型和完整对象引用隔离；需要保留的 interaction / compaction 上下文与去重标识使用同一条记录。span 模块只查询和登记完成状态，由 Observer 在结束 run 时先收尾后代，再统一释放子 span 记录，仅保留 run 的关闭标记至实例结束，用于拒绝旧任务重建。清理一个 run 不影响其他活动 run 的历史记录。

关闭必须幂等，多次调用共享同一过程；关闭开始后不再修改遥测状态。刷新和关闭失败通过 Promise 拒绝反馈，由调用边界隔离并诊断。

## 7. 行为识别与采集约束

适配层根据源证据识别对象身份、归属和生命周期，并处理重复、迟到及乱序输入。tracker 负责自身对象，协调模块负责跨对象关联、状态联动和清理；遥测层依据已提交的契约操作维护 span，不参与源证据判断。

具体识别、采集和状态管理规则见 [适配层设计](adapter.md)。观测结果的创建条件、时间、父子关系、失败分类和降级口径以 [Trace Schema](schemas/trace.md) 为准；层间提交遵循第 4 节契约，失败隔离与实例关闭遵循第 6 节。

## 8. 验收要求

- **依赖边界**：检查实际静态与动态依赖，覆盖类型导入、重导出和相对路径，避免绕过模块限制。
- **独立测试**：适配层可注入记录调用的契约实现，无需 OTel provider；遥测层可直接接受契约调用，无需构造宿主事件或 client。各 tracker 按其实际接口使用源 SDK 对象或已解析数据测试，全局事件分发与跨对象协调用协调模块测试。
- **行为一致**：验证 Trace Schema 中的对象关系、生命周期、时间、状态和字段口径，并覆盖重复通知、迟到数据、跨会话隔离、重试及恢复。
- **采集隔离**：验证正文开关、快照替换、回调乱序、跨实例隔离、关联标识清理，以及身份和传播独立于正文采集。
- **宿主不受影响**：集成/E2E 覆盖 hook 到 OTLP 的完整路径；慢导出和失败不改变业务执行或时间边界，关闭清理未完成对象且不重复导出。

验证命令及修改类型对应的必需检查见 [AGENTS.md](../AGENTS.md#required-checks-after-changes)。
