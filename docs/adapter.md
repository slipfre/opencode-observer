# 适配层设计

本文约定 `src/adapter/` 如何从 OpenCode hooks/events 和 AI SDK lifecycle 回调识别行为、采集数据并提交观测契约，覆盖重复、迟到、乱序输入及跨对象协调。

- [总体架构](architecture.md) 定义模块职责、依赖边界、契约语义和运行约束。
- [Trace Schema](schemas/trace.md) 定义观测结果的创建条件、时间、父子关系、字段及失败和降级口径。
- 本文定义适配机制；契约接口与类型见 [Observer 契约](../src/contract/observer.ts)，不在本文重复定义。

## 1. 数据源与证据边界

OpenCode hooks/events 提供用户输入、对象身份、模型 step、工具执行、压缩和权限决策等证据。适配层依据这些证据判断生命周期，再通过 Observer 提交开始、更新和结束操作。

普通 LLM 与压缩摘要 LLM 共用模型采集规则：通过支持的 AI SDK lifecycle 接口采集模型数据，独立于宿主 AI SDK 的 OTel 导出开关。跳过 SDK 的运行路径使用事件数据降级；依赖版本由包配置维护。

生命周期证据和 SDK 内容快照分别处理：SDK 正文回调不替代模型 step 的完成或失败证据，也不改变结束时间和用量的来源。请求准备和事件观察边界的测量限制见 [Trace Schema §8.4–8.5](schemas/trace.md#84-retry-attributes)，不能据此推断精确网络耗时、首块延迟或每次重试起点。

内容解析、保留和提交统一遵循 [总体架构 §4](architecture.md#4-观测契约) 的 `captureContent` 约束。正文关闭时仍可关联显式输出格式；上下文传播遵循 [总体架构 §5.2](architecture.md#52-传播边界)。

## 2. 用户输入识别与去重

识别用户输入时区分真实输入、系统生成的续接文本（synthetic）和压缩标记；压缩摘要不参与用户请求或最终答复选择。具体输入范围和混合消息规则见 [Trace Schema §5–6](schemas/trace.md#5-prefixrun)。

同一条用户消息按 session ID 和 message ID 去重，在插件实例生命周期内只登记一次。去重须在记录输入、创建 interaction 或开启 run 前完成，重复通知不能再次触发这些操作。

执行中的追加输入（steer）交给 interaction 跟踪逻辑处理，协调模块统一维护消息归属与最终答复选择。旧操作继续使用已确认的 owner，不因当前 interaction 改变而重新归属；交互切换的结束时间和输出语义见 [Trace Schema §6.2](schemas/trace.md#62-生命周期)。

## 3. LLM 关联与采集

### 3.1 生命周期证据归并

提交 LLM 开始操作前，须同时取得调用开始证据、明确的 assistant 身份和可识别 parent。优先在请求准备阶段建立关联，以便发送前传播上下文；未取得该关联时使用首次模型 step 的观察时间。元数据迟到时保留原观察时间，仅有 assistant 或结束通知不能补造调用。

同一 assistant 的重复 step 和重试归并到同一逻辑 LLM。新 step 替换前次尝试的数据，重复通知不清空当前快照，旧尝试的迟到内容不能覆盖新结果。用量只接受有效完成数据，不将初始化零值当作成功结果；用量归一化规则见 [Trace Schema §8.1](schemas/trace.md#81-身份模型和用量)。

### 3.2 请求绑定与实例隔离

以 session 内的用户消息、provider、model 和 agent 等信息唯一确认调用及其 parent，再建立一次性请求关联。后续 SDK 回调须校验调用身份和绑定有效性，不能仅凭 session ID 归属。标题、歧义调用或缺少 parent 的摘要调用不采集。

内部关联标识在 provider 执行前移除，不进入契约或 span。SDK 回调的进程级注册必须隔离插件实例，各实例只接收自身绑定的调用；实例释放时清理监听器和待关联记录，使旧绑定失效。共享回调的失败隔离遵循 [总体架构 §6.1](architecture.md#61-执行与失败隔离)。

### 3.3 数据转换与快照提交

适配层将当前 step 的 SDK 消息、请求参数、工具定义及 headers 转换为契约快照。输入与输出分别优先使用结构化快照，缺失时分别使用文本降级数据；不能用一侧快照是否存在推断另一侧数据是否可用。消息来源、生成内容范围、转换规则及可见 headers 的限制见 [Trace Schema §8.2–8.3](schemas/trace.md#82-消息与系统指令)。GenAI/HTTP 属性编码由遥测层完成。

请求、输入、输出和响应 headers 通过 [LlmUpdate](../src/contract/observer.ts) 提交，遵循契约的快照替换与清除语义。适配层在新请求或新输入到达时提交对应更新，使前次输出及相关响应数据按契约清除；未知值和已知空结果保持区分。

新绑定或新 step 必须使旧异步结果失效。输出格式和工具 Schema 解析不阻塞宿主，失败按字段降级；响应到达、绑定失效、调用结束或实例关闭后的迟到解析结果忽略，不延迟已观察响应的提交。

### 3.4 开始与结束事件的乱序

SDK 快照早于调用开始证据时可以暂存，确认 LLM 后再提交。成功结束事件早于正在等待的输出回调时，可以保留原结束时间，待正文提交后再提交结束操作。

idle、终止错误或关闭负责清理等待中的调用，不能无限等待正文回调。该协调过程不产生额外观测对象，也不以正文回调到达时间替换已观察的结束时间。

## 4. 跨对象协调

协调模块负责确定对象间的归属、传递影响其他对象的结果，并安排关联对象的清理顺序。tracker 之间的协作由协调模块装配，依赖边界遵循 [总体架构 §2.3](architecture.md#23-各层内部组织)。

### 4.1 归属解析

| 对象关系                 | 适配层使用的关联证据                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| run / interaction        | 以真实用户消息确认 interaction，统一维护该消息在 run 中的归属及最终答复选择                                             |
| interaction / tool       | 通过工具所属 assistant 确认 interaction，并用 call ID 区分工具调用                                                      |
| interaction / compaction | overflow 触发的压缩优先通过触发超限的模型调用确认 interaction；自动压缩通过标记压缩动作的源事件或 hook 确认 interaction |
| compaction / 摘要 LLM    | 通过摘要调用对应的压缩标记确认 compaction                                                                               |
| tool / permission.check  | 仅匹配同一 session 内具有精确调用引用的活动工具                                                                         |
| task / 子 run            | 子 run 创建前确认活动 task 与子 session 的精确关联；后台任务不建立前台嵌套                                              |

已提交的父子关系不事后改挂。缺少父对象时按 [Trace Schema](schemas/trace.md#3-trace-拓扑) 对应规则省略或记录独立 run，不补造未知关系。

### 4.2 状态联动

协调模块根据源证据判断 overflow 是否可恢复，在恢复期间保持 run/interaction 打开，确认终止失败后才提交结束操作。interaction 的局部错误不直接推断为 run 失败，子对象失败也不自动判定为父对象失败。

人工权限拒绝按已完成决策处理，并通知对应工具进行错误分类。各对象最终采用的状态和错误口径见 [Trace Schema §11](schemas/trace.md#11-状态与错误汇总)。

## 5. 迟到数据与清理

工具元数据迟到时可以暂存，终态证据完整时按 [Trace Schema §9.2](schemas/trace.md#92-生命周期与状态) 的条件补建，首个终态确定后忽略旧状态。

去重记录只保留必要标识，不保留正文。输入与已结束对象的去重记录保留到实例关闭，防止旧输入进入下一次 run。已结束 interaction/compaction 的轻量上下文保留至 run 结束，供归属明确的迟到操作使用。

权限请求的待处理容量必须有界，淘汰时提交清理结果，状态口径见 [Trace Schema §10.2](schemas/trace.md#102-生命周期与状态)。工具结束时清理未回复的权限请求；task 结束时先清理子 run，再释放活动绑定，后续任务不继承旧引用。

实例关闭时释放源状态、监听器及绑定；适配层与遥测层的关闭顺序、幂等要求和导出职责见 [总体架构 §6.2](architecture.md#62-生命周期契约)。
